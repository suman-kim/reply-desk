# reply-desk · 유튜브 댓글 에이전트 대시보드

영상을 **불러오고**, **고르고**, 버튼 한 번이면 **크롬 프로필이 열려 직접 타이핑으로 댓글을 다는** 대시보드입니다.
AI가 영상의 맥락을 읽고, 시청자 한 사람이 쓴 것처럼 홍보 대상(예: 운명원 연애 사주)으로 자연스럽게 이어지는 댓글 초안을 씁니다.

- 시연 영상: _(유튜브 링크를 여기에)_ · 대본과 챕터: [`docs/demo/`](docs/demo/)
- 내 컴퓨터에서 실행합니다. 웹에 올린 페이지는 내 컴퓨터의 크롬 프로필을 열 수 없기 때문입니다.

---

## 한눈에 보기

| 단계 | 화면 | 하는 일 |
|---|---|---|
| ① 영상 불러오기 | 대시보드 | 주제의 검색어로 유튜브 영상을 모아 썸네일·제목·채널·올린 날짜·조회수로 보여 줍니다. 관련도·조회수·최신순 정렬, 링크로 직접 추가 |
| ② 영상 고르기 · 초안 | 작업 상세 | AI가 영상과 인기 댓글을 읽고 **주제 매칭 %**와 **근거 장면**을 찾은 뒤, **시청자 고민 한 줄**을 꾸며 그 사람이 쓴 것처럼 초안을 씁니다. 코드가 자동 검사 |
| ③ 댓글 달기 | 작업 상세 | 계정의 크롬 프로필이 열려 댓글 창 찾기 → **한 글자씩 입력** → 게시 → **내 댓글 확인**까지 진행하고, 진행 단계와 크롬 화면을 대시보드에 보여 줍니다 |
| 기록 | 댓글 게시 목록 | 어느 영상에 · 어느 계정으로 · 무슨 댓글을 · 성공/실패를 시간순으로, 실패하면 원인과 화면 캡처 |

## 주요 기능

**계정 (크롬 프로필)**
- 계정마다 전용 크롬 프로필 폴더를 만들고, 그 크롬에서 사용자가 직접 로그인합니다. 비밀번호는 저장하지 않습니다.
- [연결 확인]으로 로그인·유튜브 채널·한국어 화면을 점검합니다. 여기 등록한 계정의 채널이 곧 '내 채널'입니다.
- 게시할 계정을 고르거나, 주제마다 차례대로 자동 배정합니다. 로그인이 풀린 계정은 자동 배정에서 빠집니다.

**주제 (홍보 대상 하나 = 주제 하나)**
- 홍보 대상 설명, 검색 키워드, 올린 날짜 범위, 목록 순위 기준, 한 번에 불러올 수
- 댓글 말투, 글자 수(기본 40~120자), 추가 금지 표현
- 다른 채널 영상에 붙일 광고 표시(기본 `[광고]`), 쓸 계정, 주제별 하루 상한, 진행/일시정지

**AI 분석과 초안**
- 분석: 이 영상이 주제와 얼마나 맞는지(0~100%), 고른 이유, 근거 장면(시점·인용)과 장면 핵심 단어
- Gemini는 유튜브 영상을 직접 보고, 영상을 못 보는 모델은 영상 설명과 인기 댓글로 분석합니다.
- 초안: **시청자 고민 한 줄**을 먼저 꾸민 뒤, 그 사람처럼 장면을 짚어 홍보 대상으로 이어지는 댓글을 씁니다.
- **글 모양 카드**: 초안마다 코드가 쓰는 사람·말투·시작·브랜드를 꺼내는 방식과 자리·길이를 무작위로 고르고, 최근 조합은 피합니다.
- **말버릇 피하기**: 같은 주제의 최근 초안에 자주 나온 말을 "쓰지 말 것"으로 넘깁니다.
- AI는 Gemini · Claude · OpenAI · Ollama(내 PC) 중에서 분석과 작성을 따로 고릅니다. 모델 목록·가격·무료 표시를 설정에서 봅니다.

**자동 검사** (걸리면 걸린 이유를 붙여 AI가 한 번 더 씁니다. 사람이 고치면 바로 다시 검사합니다)

| 검사 | 내용 |
|---|---|
| 길이 | 주제의 최소~최대 글자 수 (광고 표시는 세지 않음) |
| 장면 언급 | 근거 장면의 시점이나 핵심 단어가 들어 있는지 |
| 브랜드 언급 | 브랜드 단어가 딱 한 번 |
| 링크·해시태그 없음 | 링크·해시태그를 쓰지 않음 |
| 지어낸 후기 없음 | 받아 봤다·다녀왔다·맞았다처럼 써 본 척하는 말 금지 |
| 금지 표현 없음 | 주제별 금지 표현 |
| 최근 초안과 다름 | 최근 초안과 거의 같은 글이나, 대부분에 나온 말버릇을 또 쓰면 걸림 |
| 이미 단 댓글과 다름 | 같은 영상에 더 달 때, 이미 단 댓글과 같은 글(띄어쓰기·광고 표시 무시)이면 걸림. 단 댓글이 없으면 건너뜀 |

**그 밖에**
- 실시간 진행(SSE): 초안 작성·게시 상태가 모든 화면에 바로 반영되고, 끝나면 알림을 띄웁니다.
- 오른쪽 작업 패널: 전체 · 게시 대기 · 작성 중 · 확인 필요 · 게시 완료
- 유튜브 API 할당량 아끼기: 최근 검색 결과를 재사용하고, 다음에는 새로 올라온 영상만 검색합니다.

## 작동 방식

```
 [코드] 영상 모으기  →  [AI] 판단 · 초안  →  [코드] 검증  →  [사람] 확인  →  [크롬] 게시
  유튜브 API 검색        주제 매칭 %           인용 원문 대조     [댓글 달기]      프로필 열기
  조회수·시각은 API 값    근거 장면              자동 검사 8가지                     한 글자씩 입력
  검색 재사용             시청자 고민 한 줄       걸리면 다시 쓰기                    게시 → 내 댓글 확인
                         댓글 초안                                                 실패 시 단계·원인·캡처
```

- **판단은 AI, 사실 확인은 코드**: 조회수·올린 시각·채널 같은 숫자는 AI가 쓰지 않고 API 값을 코드가 넣습니다. AI가 고른 인용은 영상 설명·인기 댓글 원문에 있는지 코드가 대조해, 없으면 버립니다.
- **결정은 사람**: 주제 매칭이 낮아도 색으로 알리기만 하고 막지 않습니다. 게시는 사람이 [댓글 달기]를 눌러야 시작합니다.

## 운영 규칙 (코드가 강제)

| 규칙 | 어떻게 지키나 |
|---|---|
| 영상당 댓글 1개 (기본) | 이미 댓글을 단 영상은 다른 주제가 단 것까지 차단 규칙이 막고, 새 초안도 쓰지 않습니다. 설정 → 게시의 **같은 영상에 댓글 더 달기**를 켜면 게시 완료 화면의 [새 초안 쓰고 한 번 더 달기]로 계정과 상관없이 더 달 수 있습니다. 새 초안은 이미 단 댓글을 받아 겹치지 않게 씁니다 |
| 같은 초안은 한 번만 | 게시 기록 표의 부분 유일 인덱스(`status='success'`인 행은 초안마다 하나)로 **데이터베이스가 직접** 막습니다. 게시한 초안은 고칠 수 없어 기록과 같은 글로 남습니다 |
| 하루 게시 상한 | 전체 상한(설정, 기본 10)과 주제별 상한을 한국 시간 날짜로 셉니다 |
| 같은 영상 동시 게시 | 게시 중인 행도 영상마다 하나만 둡니다 |
| 게시 전 차단 사유 | 영상 미선택 → 초안 없음 → 이미 단 영상(기본) → 이미 게시한 초안 → 검사 미통과 → 상한 → 일시정지 → 게시 중 → 계정 없음/로그인 풀림 순서로, 먼저 걸린 이유 한 줄을 버튼 아래에 보여 줍니다 |
| 광고 표시 | 다른 채널 영상의 초안 맨 앞에 주제의 광고 표시를 붙입니다(내 채널 영상에는 붙이지 않음) |

## 기획 의도

1. **광고가 아니라 시청자 한 사람의 이야기처럼.** 영상 속 장면을 짚고, 시청자 고민 한 줄을 가진 사람이 쓴 것처럼, 매번 다른 모양으로 씁니다.
2. **판단은 AI, 숫자와 규칙은 코드, 마지막 결정은 사람.** AI가 틀려도 지어낸 숫자·인용은 걸러지고, 게시는 사람이 확인한 것만 나갑니다.
3. **비용과 할당량을 아끼는 구조.** [영상 불러오기]는 영상만 모으고 초안은 고른 영상만 씁니다. 유튜브 검색은 재사용하고 새 영상만 찾습니다.
4. **실제 사람처럼 게시.** 평소 쓰는 기본 크롬이 아니라 계정마다 지정한 프로필 폴더(`--user-data-dir`)로 열고, 한 글자씩 입력하고, 올라간 댓글까지 확인해야 성공으로 남깁니다.

## 기술 구성

| 부분 | 쓴 것 |
|---|---|
| 서버 `server/` | NestJS, TypeORM, PostgreSQL 17(Docker), Zod 검증, SSE |
| 화면 `web/` | React, Vite, TanStack Query, React Router |
| 브라우저 자동화 | Playwright(core) + Google Chrome 프로필 (열려 있는 크롬에는 원격 연결로 붙음) |
| AI | Vercel AI SDK(Gemini · Claude · OpenAI), Ollama REST API |
| 외부 API | YouTube Data API v3 |

```
reply-desk/
├─ server/            NestJS API (4100) · DB 마이그레이션 · 단위/e2e 테스트
│  └─ src/
│     ├─ videos/      영상 검색·불러오기·순위
│     ├─ drafts/      분석·초안 작성·대기열 (variety/: 글 모양 카드·말버릇)
│     ├─ checks/      자동 검사 (검사 하나 = 클래스 하나)
│     ├─ rules/       게시 차단 규칙 (규칙 하나 = 고리 하나)
│     ├─ publish/     크롬으로 게시 5단계
│     ├─ browser/     크롬 프로필 열기·붙기
│     ├─ profiles/ topics/ posting/ settings/ ai/ events/ prompts/
├─ web/               대시보드 (5173, /api는 4100으로 넘김)
├─ docs/              설계 문서 · 시연 대본
├─ design/            화면 시안·캡처
└─ tools/demo-video/  시연 영상 녹화·편집 스크립트
```

## 처음 실행 (macOS)

**준비물**: macOS, Node.js 24, Docker, Google Chrome, YouTube Data API v3 키, AI 하나 이상(Gemini·Claude·OpenAI 키 또는 Ollama)
> 크롬 로그인 창을 macOS `open` 명령으로 띄우므로 지금은 macOS에서 동작합니다.

```bash
# 1) DB (PostgreSQL 17, 127.0.0.1:5441)
cd server
docker compose up -d

# 2) 환경 변수: 예시를 복사해 키를 채운다 (.env* 파일은 저장소에 올라가지 않는다)
cp env.example .env.development
#   YOUTUBE_API_KEY, GEMINI_API_KEY / ANTHROPIC_API_KEY / OPENAI_API_KEY 중 쓰는 것
#   PROFILES_ROOT(크롬 프로필 폴더), SCREENSHOTS_DIR(게시 캡처 폴더)

# 3) 서버 (http://localhost:4100, 시작할 때 DB 마이그레이션을 자동 적용)
npm install
npm run start:dev

# 4) 화면 (새 터미널, http://localhost:5173)
cd ../web
npm install
npm run dev
```

**처음 한 번 하는 일**
1. **계정 관리** → [새 프로필 추가] → 이름 정하기 → [크롬 열기] → 열린 크롬에서 직접 로그인 → [로그인했어요]
2. **설정** → AI 탭에서 분석·작성에 쓸 AI와 모델 고르기 (Ollama를 쓰면 Ollama 탭에서 주소 설정)
3. 왼쪽 메뉴 **+ (새 주제)** → 홍보 대상·검색어·쓸 계정 정하기 → [주제 만들기]
4. 대시보드 [영상 불러오기] → 영상 고르기 → [초안 작성] → 확인·수정 → [댓글 달기]

## 테스트

```bash
# 서버: 단위 테스트, e2e(테스트 DB reply_desk_test, 가짜 유튜브·AI·크롬), 린트
cd server
npm test
npm run test:e2e
npm run lint

# 화면: 테스트, 린트, 빌드
cd ../web
```

e2e는 실제 유튜브에 댓글을 달지 않습니다. 실제 게시 시험은 `server/test/live/`에 따로 있습니다(내 채널 영상에만).

## 시연 영상 다시 만들기

`tools/demo-video/`의 스크립트로 녹화부터 자막·음성까지 만듭니다. 자세한 장면은 [`docs/demo/2026-11-14-demo-video-script.md`](docs/demo/2026-11-14-demo-video-script.md).

```bash
cd tools/demo-video
node tts.mjs out        # 장면별 한국어 음성 (macOS say, Yuna)
node captions.mjs out   # 자막·장면 이름·엔딩 그림 (투명 PNG)
node record.mjs out     # 대시보드를 자동 조작하며 주 모니터 녹화 (실제 게시 1회, DRY=1이면 연습)
node edit.mjs out       # 자르기·빨리 감기·자막·음성 → out/final.mp4
```

- 녹화(`record.mjs`)는 macOS 화면 기록 권한이 있는 터미널에서 실행합니다. ffmpeg가 필요합니다(`brew install ffmpeg`).
- `DRY=1`이 아니면 실제 유튜브에 공개 댓글이 하나 달립니다.
