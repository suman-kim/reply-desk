# 유튜브 댓글 에이전트 대시보드 — 디자인 계획안

Nov 13, 2026 · @suman

## 목표와 디자인 원칙

이 화면의 목표는 2\~3분 시연 영상에서 심사위원이 설명 없이 세 칸을 따라가고, AI가 왜 이 영상과 이 댓글을 골랐는지 한눈에 납득하게 하는 것이다. 평가 배점마다 화면에서 증거가 보이는 자리를 하나씩 정해 둔다.

| 평가 항목 (배점) | 화면에서 보여줄 것 | 원칙 |
| --- | --- | --- |
| 실제 게시 (25) | ③ 진행 5단계, 크롬 창 미리보기, 게시 완료와 댓글 보기 | 진행을 숨기지 않는다 |
| 맥락 이해 (25) | 근거 장면(시점 + 인용), 영상 속 고민 한 줄 | 근거를 먼저 보여준다 |
| 운명원 유도 (20) | 댓글을 이렇게 쓴 이유: 운명원으로 넘어간 방식 | AI 판단을 문장으로 설명한다 |
| 운영 규칙 (15) | 헤더의 오늘 게시 n/10, 규칙 바, 차단 사유, 게시 기록 | 규칙은 늘 보이게, 막을 땐 이유를 |
| 사용성 (10) | ①②③ 번호와 한 줄 안내, 단계마다 버튼 하나만 강조 | 다음 행동은 하나만 눈에 띄게 |
| 제작 의도 (5) | 숫자는 코드, 판단은 AI, 검증은 코드라는 구조가 화면에 드러남 | 자동으로 한 일은 결과와 이유를 같이 |

원칙 다섯 가지:

1. 단계마다 가장 강한 버튼은 하나다. ①은 \[영상 불러오기\], ③은 \[댓글 달기\]만 진한 색을 쓴다.
2. 숫자와 판단을 구분한다. 조회수·시각·글자 수는 고정폭 글꼴, AI 판단은 문장으로 쓴다.
3. 자동으로 하는 일은 진행률로 보인다. 정렬과 초안 작성이 "2/5"처럼 셀 수 있게 움직인다.
4. 막을 때는 이유를 쓴다. 비활성 버튼 아래에 원인 한 줄이 항상 붙는다.
5. 녹화 화면이 기준이다. 1440px 폭에서 글자는 12px 이상, 핵심 문장은 14px 이상이다.

하지 않을 것: 운명원 로고나 브랜드 흉내, 장식용 애니메이션과 그라데이션, 화면을 가리는 팝업.

## 사용 흐름

&#91;embedded content: 사용 흐름 · 자동 4단계, 사람 확인 후 게시\]

검사를 통과한 초안만 ②에 올라오고, \[댓글 달기\]는 내 채널·영상당 1개·하루 10개 규칙을 모두 지킬 때만 열린다.

## 주제 (홍보 대상)

주제 하나는 홍보할 대상 하나다. ①②③ 과정과 기록은 고른 주제 안에서만 돌고, 규칙 일부는 주제와 상관없이 전체에 걸린다.

| 설정 | 예시 (운명원) | 쓰는 곳 |
| --- | --- | --- |
| 이름 | 운명원 연애 사주 | 주제 목록, 주제 머리 |
| 유도 대상 | 운명원 · 연애 사주 잘 보는 곳 | 댓글 작성, 브랜드 언급 검사 |
| 검색 키워드 | 연애, 썸, 재회 | ① 불러오기 |
| 영상 조건 | 최근 7일, 조회수 높은 순 | ① 정렬 |
| 댓글 말투 | 20\~30대 시청자, 공감형 구어체 | 댓글 작성 |
| 글자 수 | 40\~120자 | 자동 검사 |
| 추가 금지 표현 | 주제별로 입력 | 자동 검사 (공통: 링크·해시태그·지어낸 후기) |
| 쓸 프로필 | 유튜브1, 유튜브2 | ③ 계정 선택 |
| 하루 상한 | 5개 | ③, 주제 목록 |

| 규칙 | 범위 |
| --- | --- |
| 영상당 댓글 1개 | 전체. 다른 주제가 이미 댓글을 단 영상도 막힘 |
| 하루 상한 | 전체 10개 안에서 주제별로 나눠 씀 |
| 내 채널 영상만 게시 | 전체 |
| 기록 | 주제별 보기와 전체 보기 |

주제 목록의 항목은 이름, 오늘 게시 n/상한, 초안 대기 수, 상태(진행 중·일시정지)를 보여준다. \[+ 새 주제\]를 누르면 오른쪽에서 설정 창이 열리고, 저장 전에 \[샘플 초안 만들기\]로 말투와 브랜드 연결을 미리 확인한다.

## 계정 (크롬 프로필) 등록

계정 관리 화면에서 크롬 프로필과 유튜브 계정을 연결하고, 등록한 계정의 채널이 곧 게시가 허용되는 '내 채널'이 된다. 대시보드 헤더의 \[계정 관리\]로 들어간다.

1. 프로필 폴더 만들기: 이름(예: 유튜브4)을 정하면 `~/yt-agent/profiles/youtube4` 폴더를 만든다.
2. 크롬 열고 직접 로그인: 그 폴더로 크롬을 열고, 사람이 크롬 창에서 구글 로그인을 한다. 비밀번호는 대시보드에 입력하지도 저장하지도 않는다.
3. 채널·한국어 화면 확인: youtube.com에서 로그인된 채널 이름과 채널 ID를 찾고, 화면 언어가 한국어인지 확인한다.
4. 연결 완료: 채널 ID가 내 채널 목록에 들어간다.

프로필 카드는 구글 계정(가림), 채널 ID, 폴더, 마지막 확인, 화면 언어, 오늘 게시, 쓰는 주제를 보여준다. 로그인이 풀린 프로필은 경고 띠와 \[크롬 열어 다시 로그인\]을 보여주고, 다시 로그인할 때까지 자동 배정에서 빠진다. 대시보드 헤더에도 "유튜브2 로그인 필요"처럼 상태가 뜨고, 그 프로필을 고르면 게시 버튼이 잠긴다.

## 초안 목록

AI가 쓴 초안을 한곳에서 조회하고, 행을 누르면 오른쪽 상세 패널에서 고치거나 게시·다시 게시한다. 대시보드 헤더의 \[초안 목록\]으로 들어간다.

| 상태 | 뜻 | 상세 패널의 게시 버튼 |
| --- | --- | --- |
| 게시 대기 | 내 채널 영상, 검사 통과 | \[댓글 게시\] |
| 실패 | 게시를 시도했지만 실패 | \[다시 게시\] |
| 검사 미통과 | 초안이 자동 검사에 걸림 | 잠김, 고치면 바로 다시 검사 |
| 게시 완료 | 이미 댓글을 단 영상 | 잠김 (영상당 1개) |
| 초안만 | 다른 채널 영상 | 잠김 (내 채널만) |

목록 위에는 상태(개수 포함), 주제, 검색(영상 제목·댓글 내용) 필터가 있다. 상세 패널은 고민 한 줄, 고른 이유, 수정 가능한 초안, 자동 검사, 쓴 이유, 게시 기록(성공·실패), 계정 선택과 게시 진행 단계를 보여준다. 로그인이 풀린 계정을 고르면 게시가 막힌다.

## 칸별 상세

세 칸은 위에서 아래로 읽는 순서가 곳 판단 순서다. ② 칸이 가장 넓고, ①과 ③은 같은 폭이다.

### ① 영상 불러오기

- 제목과 안내 한 줄: "'연애' 최신 영상을 조회수 높은 순으로 정렬하고, 초안까지 자동으로 써둬요"
- &#91;영상 불러오기\] 주요 버튼, 높이 48px
- 목록 머리: "n개 영상 · 조회수 높은 순"
- 영상 카드: 순위, 썸네일(104×60, 재생 시간), 제목 최대 2줄, 채널·올린 날짜, 조회수, 상태 배지
- 배지 4종: 초안 작성 중, 초안 준비됨, 내 채널, 댓글 완료

| 상태 | 버튼 문구 | 목록 |
| --- | --- | --- |
| 처음 | 영상 불러오기 | 점선 빈 상태 안내 |
| 불러오는 중 | 최신 영상 불러오는 중… | 빈 카드 틀 4개 |
| 초안 작성 중 | 초안 자동 작성 중 (2/5) | 카드 배지가 순서대로 "준비됨"으로 바뀜 |
| 준비 완료 | 다시 불러오기 | 1위 영상이 자동 선택됨 |
| 실패 | 다시 시도 | 원인 한 줄 (예: API 하루 할당량 초과) |

### ② 영상 선택

위에서 아래 순서:

1. 링크 직접 입력 + \[추가\]
2. 영상 머리: 제목, 채널, 날짜, 조회수
3. 이 영상을 고른 이유 (남색 상자, 번호 2\~3개)
4. 영상 속 고민 한 줄 (금색 상자, 굵게)
5. 근거 장면·인기 댓글 (시점 칩 + 인용)
6. 댓글 초안 (수정 가능, n/120자)
7. 이 댓글을 이렇게 쓴 이유 (회색 상자)
8. 자동 검사 5개: 길이, 장면 언급, 운명원 언급, 링크·해시태그 없음, 지어낸 후기 없음
9. &#91;다시 생성\] 보조 버튼

상태는 다섯 가지다: 선택 전(점선 안내), 초안 작성 중, 준비됨, 직접 수정됨(이유 상자에 "AI 초안 기준" 표시), 다시 생성 중.

### ③ 댓글 달기

1. 게시할 계정: 유튜브1·2·3·자동 배정 4칸 버튼, 아래에 "이번 차례: 유튜브2"
2. 게시 대상: 영상 제목 + "내 채널" 또는 "다른 채널 · 초안까지만" 배지
3. &#91;댓글 달기\] 화면에서 가장 큰 버튼 (높이 52px)
4. 차단 사유 한 줄 (버튼이 잠겼을 때만)
5. 진행 5단계: 프로필 여는 중 → 댓글 창 찾는 중 → 한 글자씩 입력 중 → 게시 → 내 댓글 확인
6. 크롬 창 미리보기: 실제 앱에서는 Playwright 스크린샷을 주기적으로 받아 띄움
7. 게시 완료 띠 + \[댓글 보기\]

### 게시 기록

열은 시각, 영상, 프로필, 댓글, 결과 다섯 개다. 최근 항목이 위에 오고, 실패 행에는 원인과 \[캡처 보기\]가 붙는다.

## 상태·피드백 설계

자동으로 움직이는 단계는 모두 진행 중임을 보여주고, 막히거나 실패하면 원인을 한 줄로 남긴다.

| 상황 | 화면 표시 | 위치 |
| --- | --- | --- |
| 자동 정렬·초안 작성 | 버튼에 진행률 (2/5), 카드 배지가 차례로 바뀜 | ① |
| 게시 진행 | 5단계 체크리스트, 크롬 미리보기, 입력 글자 수 (34/91자) | ③ |
| 게시 차단 | 버튼 회색 + 사유 한 줄 | ③ 버튼 아래 |
| 게시 실패 | 실패한 단계에 빨간 X + 원인, 캡처 저장, 기록에 실패 행 | ③, 기록 |
| 하루 상한 도달 | 헤더 카운터 10/10 강조, 버튼 차단 | 헤더, ③ |

차단 사유는 한 번에 하나만, 아래 순서로 먼저 걸리는 것을 보여준다.

1. 영상을 고르지 않음
2. 초안이 아직 준비되지 않음
3. 이미 댓글을 단 영상 (영상당 1개)
4. 내 채널이 아닌 영상 (초안까지만)
5. 자동 검사 미통과
6. 하루 게시 상한 도달

실패는 원인별로 문구를 정해 두고, 모두 그 순간의 화면 캡처를 남긴다.

| 실패 지점 | 기록에 남길 원인 |
| --- | --- |
| 프로필 열기 | 같은 프로필의 크롬이 이미 열려 있음 |
| 댓글 창 찾기 | 로그인이 풀림 / 댓글 창이 제한 시간 안에 뜨지 않음 / 댓글이 막힌 영상 |
| 게시 | 게시 버튼이 눌리지 않음 |
| 내 댓글 확인 | 게시 후 내 댓글이 보이지 않음 |

## 비주얼 시스템

디자인은 새 디자인 시스템 [Inyeon v2](https://claude.ai/artifact/6a8CLnrDZDCbZNu5t8C5XW)를 따른다. 흰 바탕에 쿨그레이 면으로 구역을 나누고, 원색은 일렉트릭 블루 하나만 쓴다.

| 역할 | 색 | 쓰는 곳 |
| --- | --- | --- |
| 바탕 / 카드 | #FFFFFF, 테두리 #EBECF0 | 페이지, 패널 |
| 회색 면 | #F5F6F8 (hover #EDEFF2) | 주제 사이드바, 입력창, 보조 버튼, 회색 이유 상자 |
| 글자 | #111318 / #4B505B / #646978 | 제목·본문 / 보조 / 안내·대기 |
| 주요 (일렉트릭 블루) | #2B5CFF, 옟은 바탕 #EEF3FF, 글자 #1F45D9 | 주요 버튼, 선택, 진행, 포커스, 고른 이유 상자 |
| 고민 (로즈 핑크) | #FFF0F4 바탕, #C2185B 글자 | 영상 속 고민 한 줄, 내 채널 배지 |
| 성공 / 실패 / 주의 | #067647 / #C4261B / #9A5B00 (각각 옟은 바탕) | 검사·게시 결과, 상한 임박 |

성공과 실패는 색만으로 구분하지 않고 체크·X 아이콘과 문구를 함께 쓴다. 모든 글자는 바탕 대비 4.5:1 이상이다.

| 항목 | 기준 |
| --- | --- |
| 글꼴 | Pretendard Variable (본문·제목), 고정폭은 시점·시각·글자 수·URL만 |
| 글자 크기 | 화면 제목 30 / 주제 22 / 패널 18 / 핵심 문장 15 / 본문 14 / 안내 13 / 라벨 12 / STEP 라벨 11 (px) |
| 자간 | 제목 -0.02\~-0.03em, STEP 라벨 +0.08em |
| 간격 | 4의 배수. 페이지 좌우 32, 패널 사이 20, 패널 안쪽 24 |
| 모서리 | 버튼·입력 12, 이유 상자·영상 카드 16, 패널·사이드바 24 |
| 그림자 | 패널에는 없음. 회색 면 위에 떠오른 흰 조각(선택된 주제, 세그먼트 칸)에만 옟게 |
| 눌러지는 영역 | 44px 이상, 주요 버튼 44\~54px |

컴포넌트는 14종이다: Button(primary 블루 / dark 잉크 / secondary 회색 / ghost / dashed), Badge, Spinner, StatPill, Panel, TopicItem, Field, Segmented, VideoCard, ReasonBox, CheckList, StepList, BrowserFrame, LogTable. 화면은 [대시보드 캔버스](https://claude.ai/artifact/Ks3aX5wYo8pcz6rU92DekC)에 대시보드, 새 주제 만들기, 상태 모음 세 장으로 있다.

## 문구 가이드

모든 문구는 해요체로 짧게 쓴다. 버튼은 할 일을 동사로, 진행은 "\~하는 중…", 막힘과 실패는 원인 다음에 할 일을 쓴다.

| 상황 | 쓰는 문구 | 피하는 문구 |
| --- | --- | --- |
| 주요 버튼 | 댓글 달기 | 실행, 제출 |
| 진행 | 한 글자씩 입력 중 (34/91자) | 처리 중입니다 |
| 차단 | 내 채널 영상에만 게시돼요 · 이 영상은 초안까지 | 권한이 없습니다 |
| 실패 | 댓글 창이 20초 안에 뜨지 않았어요 · 캡처를 확인하세요 | 오류가 발생했습니다 |
| 빈 상태 | \[영상 불러오기\]를 누르면 영상 목록이 여기 떠요 | 데이터 없음 |
| 완료 | 게시 완료 · 유튜브1 | 성공적으로 처리되었습니다 |

AI가 쓰는 이유 문장에는 규칙 세 가지를 둔다.

- 숫자는 코드가 넣은 값만 쓴다. AI가 조회수나 시간을 직접 쓰지 않는다.
- 항목은 2\~3개, 한 줄에 40자 안팎이다.
- 장면을 가리킬 때는 시점과 원문을 함께 쓴다 (예: 05:20 "부모님 얘기에 말을 돌린다면").

## 시연 영상 스토리보드

2분 30초 기준이고, 배점이 가장 큰 맥락 이해와 실패 없는 실제 게시에 1분 30초를 쓴다. 녹화는 대시보드와 실제 크롬 창을 좌우로 나란히 둔다.

| 시간 | 화면 | 보여줄 것 | 노리는 평가 |
| --- | --- | --- | --- |
| 0:00–0:15 | 대시보드 전체 | 세 칸 구조, 운영 규칙 바, 오늘 게시 0/10 | 사용성 |
| 0:15–0:40 | ① | 불러오기 → 조회수 순 정렬 → 초안 자동 작성 진행률 | 사용성, 맥락 이해 |
| 0:40–1:10 | ② | 1위 영상의 고른 이유 → 고민 한 줄 → 근거 장면 → 초안 → 쓴 이유 → 검사 통과 | 맥락 이해, 운명원 유도 |
| 1:10–1:20 | ② | 다른 영상 하나를 더 열어 초안이 영상마다 다른 것 | 맥락 이해 |
| 1:20–1:30 | ② | 링크 직접 입력으로 내 테스트 영상 추가 | 가점 |
| 1:30–2:10 | ③ + 크롬 창 | 프로필 열림 → 한 글자씩 입력 → 게시 → 내 댓글 확인 | 실제 게시 |
| 2:10–2:25 | ③, 기록 | 같은 영상에 다시 누르면 "영상당 1개"로 막힘, 기록에 새 행 | 운영 규칙 |
| 2:25–2:30 | 헤더 | 오늘 게시 1/10으로 마무리 | 운영 규칙 |
